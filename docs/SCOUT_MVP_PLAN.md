# Scout — Full MVP Build Plan

*Goal: ship the Scout prototype (`prototypes/scout-pink-v2.html`) as a real product, pixel-exact, with real jobs, real AI, real accounts and real payments. Scope matches the agreed business model: discovery + favorites + evidence-only AI documents + redirect apply. Automated applying (Pro) is architected for but not built in MVP.*

---

## 1. What the MVP is (and is not)

**Ships:**
1. **Onboarding** — 6 questions (role, location, level, salary floor, CV upload, alerts) + CV parsed into a structured **facts store**.
2. **Discover** — pure swipe deck of real, fresh jobs with fit score, two evidence-based reasons, one honest concern. Swipe / buttons / star fast-track / undo / detail.
3. **Favorites** — shortlist with per-job readiness chips.
4. **AI Application Studio** — evidence-only tailoring: suggestions with evidence chips, Accept / Keep original per change, tone regeneration, PDF export of tailored CV + cover letter.
5. **Preflight review → redirect apply** — user reviews everything, taps "Open official application," we open the listing and track it. On return: "Did you apply?" confirm (Handshake pattern) → creates the application record + receipt.
6. **Applications** — list + receipt per application (exact documents, timeline: Prepared → Opened listing → Confirmed applied).
7. **Accounts & plans** — Google/Apple sign-in; **Free** (20 swipes/week, 2 AI tries per job, free first kit per saved job) and **Plus** (€14.99/mo · €6.99/wk · €34.99/q, unlimited within fair use). Stripe checkout.
8. **Basics that make it legal** — privacy policy, terms, GDPR export/delete, cookie-less analytics.

**Explicitly NOT in MVP:** automated submission (Pro tier ships later on this foundation), employer screening-question autofill, WhatsApp, native App Store build (PWA first), multi-CV management.

**Beachhead:** launch with ONE vertical so the deck feels magical, not thin — recommendation: **product/UX designers in Europe** (the prototype's persona; strong ATS coverage; salary-transparent market). Second vertical (engineering) is a config change, not a build.

## 2. Architecture

```
Next.js 16 (Vercel) ──► Supabase (Auth · Postgres + pgvector · Storage)
   │                        ▲
   │ API routes             │
   ▼                        │
LLM: Groq llama-3.3-70b (parse · reasons · tailoring · verifier)
Embeddings: MiniLM/bge-small (job + profile vectors)
   ▲
   │ every 30–60 min
Ingestion worker (Supabase cron / small VPS):
  Greenhouse boards API · Lever postings API · Ashby · Workable · SmartRecruiters
Payments: Stripe (checkout + customer portal + webhooks)
Analytics: PostHog (EU cloud)
```

Same stack as talk.cv on purpose — zero new infrastructure to learn, and the RAG/embedding patterns port directly.

### Job ingestion (the make-or-break piece)
Public ATS endpoints give **free, legal, structured, fresh** job feeds directly from company career sites — exactly the "Company careers · 18 min ago" promise in the prototype:
- Greenhouse: `boards-api.greenhouse.io/v1/boards/{slug}/jobs?content=true`
- Lever: `api.lever.co/v0/postings/{slug}?mode=json`
- Ashby, Workable, SmartRecruiters: equivalent public JSON.

Build a **seed list of 1,000–2,000 companies** in the beachhead market (scrapeable from ATS directories + curated). Cron pulls every 30–60 min → normalize (title, location, remote, salary parse from description, department) → dedupe by `(source, external_id)` → embed → live. `verified_at` timestamp powers the honest freshness pill. Jobs vanish from the deck when the posting 404s (the "still open" check in Favorites).

### Matching
Score = embedding similarity (job description ↔ profile facts) + rule layer (location fit, salary floor, seniority band, remote preference). Reasons and the concern are generated by LLM **only for jobs above threshold entering a user's deck** (batch, cached per user×job) — grounded in the matched facts, so "Your 6 years in SaaS exceeds the 5-year requirement" is real, not decorative. Cost control: heuristic templates first, LLM polish on the top 30/day.

### Evidence-only studio (the trust moat)
1. CV parse (LLM) → `facts` table: roles, dates, skills, outcomes, each with an id.
2. Tailoring prompt receives ONLY the facts + job description; output = suggestions referencing fact ids.
3. **Verifier pass**: every claim in the output must map to a fact id; unmapped claims are dropped and logged. This is the hard guarantee behind "AI may reframe, never invent."
4. Accept/Keep per suggestion; tone regeneration re-runs with the same constraint.
5. Export: server-side PDF render (satori/react-pdf) of the final CV + letter → stored in Supabase Storage → attached to the application receipt.

### Metering (server-side, invisible fair-use)
`usage` table: swipes this week (Free: 20, weekly cron reset), AI tries per job (Free: 2 after the free kit), Plus fair-use (500 swipes/day, 30 generations/day). All checks in API routes — the client never enforces money logic.

## 3. Data model

```sql
profiles        (id=auth.uid, name, email, role_target, level, locations text[],
                 remote_ok, salary_min, currency, alerts, cv_path, plan free|plus,
                 stripe_customer_id, created_at)
facts           (id, profile_id, kind role|skill|outcome|education, content,
                 source_span, created_at)                       -- evidence store
companies       (id, name, slug, ats greenhouse|lever|ashby|…, feed_url, active)
jobs            (id, company_id, external_id, title, location, remote, salary_min,
                 salary_max, currency, description, apply_url, posted_at,
                 verified_at, open bool, embedding vector)
decisions       (id, profile_id, job_id, type save|pass|star, at)   -- swipe log
favorites       (profile_id, job_id, saved_at)                       -- view over decisions
job_matches     (profile_id, job_id, score, reasons jsonb, concern, cached_at)
documents       (id, profile_id, job_id, kind cv|letter, content jsonb,
                 accepted jsonb, tone, pdf_path, updated_at)
applications    (id, profile_id, job_id, status prepared|opened|confirmed,
                 confirmed_at, receipt jsonb)                        -- docs snapshot
usage           (profile_id, week_start, swipes int, gens_today int, day date)
subscriptions   (profile_id, stripe_sub_id, plan, period, status, renews_at)
```

RLS on everything; service role only in workers. Every table in migrations from day one (the talk.cv lesson).

## 4. Build phases (8 weeks, solo founder + Claude)

| Phase | Weeks | Ships | Done means |
|---|---|---|---|
| 0 · Foundation | 0–1 | Repo, CI, Supabase schema + migrations, auth (Google/Apple), CV upload → facts extraction | Sign in, upload CV, see parsed facts |
| 1 · Ingestion | 1–2 | Seed list (1k companies), Greenhouse+Lever pullers, normalizer, dedupe, freshness, embeddings | 3–5k live jobs, auto-refreshing, spot-checked |
| 2 · Deck | 2–3 | Matching + deck API; Discover UI ported pixel-exact (swipe physics, star, undo, coach, detail) | Swipe real ranked jobs with real reasons on a phone |
| 3 · Studio | 3–4 | Favorites; facts-constrained tailoring + verifier; suggestions UI; tone sheet; PDF export | Generate → accept → download an honest tailored CV+letter |
| 4 · Apply loop | 4–5 | Preflight; redirect + return-confirm; applications + receipts; "still open" checks | Full journey: swipe → tailor → apply → receipt |
| 5 · Money & law | 5–6 | Usage metering, Stripe (Plus), paywall moments (3rd try, 21st swipe), privacy/terms, GDPR export+delete | A stranger can pay and a regulator can't hurt us |
| 6 · Polish & beta | 6–7 | Onboarding funnel, PWA install, PostHog, empty/offline states, 20-user closed beta | Beta users complete the loop unaided; crash-free |
| 7 · Launch | 8 | Fix beta findings, seed content, launch (designer communities, Product Hunt) | Public, measured, first organic signups |

Each phase is demo-able on a phone. Nothing depends on a phase after it.

## 5. Costs (monthly, MVP scale)

Supabase Pro $25 · Vercel $0–20 · LLM $50–150 (parsing + tailoring; embeddings negligible) · PostHog free tier · Stripe % only · domain. **Under €250/month** until real traction; the ingestion VPS (€10–20) only if cron limits bite.

## 6. KPIs (first 60 days)

- Onboarding completion >60% · Deck: save rate 10–20%, ≥30 swipes/first session
- Studio: generation on ≥50% of saves; accept rate >70% (suggestion quality)
- Apply: redirect CTR on ready docs >40%; confirmed-applied >50% of redirects
- Retention: D7 >20% · Money: Free→Plus 3–5% at the two paywall moments
- Trust: zero verifier escapes (claims without evidence) — audited weekly

## 7. Risks & pre-decided answers

- **Thin/stale deck** → beachhead vertical + 1k-company seed + freshness checks; never show a dead link twice.
- **Salary missing** on many postings → parse when present, show "not listed" honestly, never estimate silently.
- **LLM invents experience** → verifier is a blocking gate, not a warning; log every drop.
- **ATS feed changes** → per-source adapters with health alerts; sources are additive.
- **Apple tax later** → web/PWA first keeps Stripe economics; Capacitor wrapper only after PMF.
- **Scope creep toward auto-apply** → Pro stays a waitlist button until Plus revenue exists.
